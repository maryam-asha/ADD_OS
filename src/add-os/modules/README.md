# `modules/` — وحدات ADD OS

فارغ عمداً. تُبنى الوحدات واحدةً تلو الأخرى بالترتيب المتفق عليه:

1. **الأساس المكاني والصلاحيات** — فرع ← مبنى ← مساحة
2. **العضويات والمحفظة**
3. **الحجوزات**
4. **التحكم بالدخول** (الأبواب الذكية)
5. **المدفوعات**
6. **الفعاليات وبرامج الاحتضان**

## الشكل المقترح للوحدة الواحدة

```
modules/<module-name>/
├── components/   مكوّنات خاصة بالوحدة
├── composables/  منطق قابل لإعادة الاستخدام داخل الوحدة
├── stores/       متجر Pinia للوحدة
├── types/        أنواع الوحدة
├── views/        صفحات الوحدة (تُربط في الراوتر)
├── lang/ar.json  ترجمات الوحدة (تُدمج في add-os/lang/ar/index.ts)
└── routes.ts     مسارات الوحدة
```

هذا اقتراح لا التزام — يُحسم عند بناء الوحدة الأولى.

## نقطتان تحتاجان انتباهاً عند أول وحدة

- **التسجيل التلقائي للمكوّنات:** `unplugin-vue-components` مضبوط على
  `dirs: ["src/components/cards"]` فقط في [`vite.config.ts`](../../../vite.config.ts).
  مكوّنات الوحدات تحتاج استيراداً صريحاً، أو توسيع `dirs`.
- **الراوتر:** [`src/router/index.ts`](../../router/index.ts) ملف مختلط
  (بنية أساسية + مسارات توضيحية). مسارات الوحدات تُضاف كملفات `routes.ts`
  مستقلة داخل الوحدة، ويكتفي الراوتر باستيرادها.
